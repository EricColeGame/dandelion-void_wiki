## What the Dandelion Void Demo Is (and What It Isn't)

A demo is a deliberately limited build. Sometimes it's a prologue — a self-contained opening chapter. Sometimes it's a vertical slice, a single polished segment pulled from the middle of the game to show the mechanics at their best. Occasionally it's a time-boxed trial that locks after a set number of sessions.

It is not a beta, not early access, and not a promise that every system you touch will survive into the final release. Developers cut demos to answer one question: does the core loop land with players who have no context and no sunk cost?

Because demo builds are assembled well before launch, details like playable area count, slice length, and supported platforms can shift between the demo and the full game. Treat the Dandelion Void demo as a snapshot, not a contract.

### Why a Demo Matters in a Release Cycle

Demos do three jobs at once:

- **They filter.** Players who bounce off the demo rarely buy — and that's a feature, not a bug.
- **They convert.** A strong slice moves wishlists and preorders more reliably than any trailer.
- **They inform.** Every bug report and balance complaint lands while changes are still cheap.

If you're deciding whether to follow this release, the demo is the most honest data point you'll get before launch day.

## What to Expect When You Launch It

Demo builds are usually less optimized than the shipping version. That's not a red flag; it's a resource-allocation reality. The last few months of development are when performance passes, LOD tuning, and load-time work actually happen.

### Scope, Pacing, and Content

Most demos run somewhere between twenty minutes and two hours, and they're designed to end on a hook. Don't read a short runtime as a short game. Read it as a curated excerpt.

If the Dandelion Void demo opens with a tutorial, resist the urge to skip it. Tutorialization is often the most revised part of a demo, and it tells you what the developers believe the game's core verb is.

### Settings Worth Touching First

| Setting | Why it matters in a demo | Reasonable starting point |
|---|---|---|
| Resolution / render scale | Demo builds often ship before optimization passes | Native resolution, then lower render scale |
| Shadows and lighting | Typically the single largest GPU cost | Medium |
| Frame rate cap / V-Sync | Reduces heat, fan noise, and micro-stutter | Cap at your display's refresh rate |
| Motion blur / film grain | Personal taste; can also cause discomfort | Off until you know how you feel |
| Subtitles and text size | UI scaling is frequently unfinished in demos | On; enlarge if available |
| Accessibility options | Often incomplete pre-launch | Check early and report gaps |

### Demo vs. Full Release: What Usually Changes

| Element | Demo build | Full release |
|---|---|---|
| Content scope | One slice, prologue, or vertical cut | Complete campaign or core mode |
| Save data | Separate profile, often wiped | Persistent, usually cloud-synced |
| Performance | Pre-optimization | Post-optimization pass |
| Balance | Rough values, wide tolerances | Tuned against player data |
| Achievements | Frequently disabled | Enabled |
| Price | Free | Paid, price varies |

## Tips for Getting the Most Out of the Dandelion Void Demo

You only get one first playthrough. Spend it well.

- **Play the intended path first.** Finish the main route before you go looking for secrets. You'll understand the pacing before you break it.
- **Then break it.** Walk into walls, spam inputs, pause during cutscenes, alt-tab, and reload a checkpoint. This is where the useful bug reports come from.
- **Take notes as you go.** Three things you loved and three you'd change is a better feedback set than a paragraph of vibes.
- **Check the settings menu for accessibility gaps** — remapping, subtitle size, colorblind modes, difficulty toggles.
- **Time your session.** Knowing how long the slice actually took you is useful context for other players.
- **Watch someone else play.** Watching a friend fumble the controls reveals design problems you stopped noticing.
- **Don't judge the story from the opening.** Demos end on hooks; the payoff is usually elsewhere.
- **Uninstall cleanly.** Demo builds sometimes leave config files behind that conflict with the full game later.

### A Thirty-Minute Plan

| Time | What to do | Why it helps |

## Sharing Feedback That Actually Helps

Community reports move the needle when they're specific and reproducible. Vague frustration gets read and discarded; a clear reproduction path gets fixed.

| Feedback type | What to include | Where to post |
|---|---|---|
| Crash | Steps to reproduce, hardware, build number, log file | Official bug tracker or Discord |
| Balance | Encounter name, difficulty setting, what felt off | Community hub thread |
| Performance | Frame rate range, settings used, resolution | Store page forum |
| Accessibility | Which option is missing or broken | Direct developer contact form |
| Praise | What worked and why | Review section, social posts |

Two habits separate useful feedback from noise. First, separate *preference* from *defect* — "I didn't like the dodge timing" and "the dodge input drops on a 60 Hz display" are different reports. Second, search before posting. Duplicate reports are fine; a hundred duplicates of the same issue are not.

## Common Demo Problems and Quick Fixes

| Symptom | Likely cause | Fix |
|---|---|---|
| Black screen on launch | Outdated GPU drivers or missing runtime | Update drivers, verify game files |
| Controller not detected | Input API conflict with overlay software | Disable overlays, replug after launch |
| Audio out of sync | Sample rate mismatch | Set output to 48 kHz in system settings |
| Save won't load | Demo profile conflicts with a previous build | Delete the demo's config folder |
| Low frame rate in one area | Unoptimized lighting pass | Lower shadows, cap frame rate |
| Progress not carrying over | Demo uses a separate save profile | Expected — check the official FAQ |

When in doubt, verify the installation files before you reinstall. It's faster, and it resolves a surprising share of demo launch problems.

## FAQ

**Is the Dandelion Void demo free to play?**
Demos are almost always free. If a site asks you to pay for demo access, you're on the wrong page — go back to the official store listing and download from there.

**Does my progress carry over to the full game?**
Usually not. Many developers isolate demo saves so balance changes and bug fixes don't corrupt launch-day profiles. Check the official FAQ before you invest hours in a save file.

**How long is the Dandelion Void demo?**
Length varies widely between builds. Some slices run twenty minutes; others offer a couple of hours. The official store page and recent community reports are the fastest way to get a current answer.

**Should I report bugs even if the demo feels finished?**
Yes. A demo that feels polished is exactly when developers are most receptive to feedback, because changes are still cheap. Note the build number, describe what you expected, and explain what happened instead.
